# DR-screening verification set (12 real fundus photographs)

Twelve **real** retinal photographs, run through the full serve pipeline
(`DRScreeningPipeline.run`) — the same path `scripts/run_demo.py` and the
`/screen` endpoint use. Each case has the photograph (`images/`) plus a
heatmap panel, an HTML report and a JSON result (`reports/`).

Rebuild with:

```bash
python scripts/build_verification_set.py
```

## Where the images come from

| | |
|---|---|
| Corpora | APTOS-2019 (Aravind Eye Hospital, India) and IDRiD (Nanded, India) |
| Split | **held-out test** — never trained on, never validated on, never used to fit a threshold or an operating point |
| Reference grade | the corpus's own ophthalmologist label, not anything this project produced |
| Preparation | read from the original file, longest side capped at 1280 px, saved as JPEG q95. No cropping, no enhancement, no retouching — the pipeline does its own preprocessing |

Every number below is the model's output **on the exact file in `images/`**:
the build script re-runs the pipeline on the saved copy, not on the source, so
what a reviewer uploads is what was measured. Nothing is a stored answer keyed
to a filename — the console recomputes on every click.

### These replaced twelve synthetic phantoms

The previous verification set was generated by
`drscreen.data.synthetic.generate`. It exercised the plumbing, but it was
obvious at a glance that no camera took those pictures, and a screening result
carries no weight when the thing screened was drawn by the same project that
graded it. Anyone can tell the difference by opening
`git show <old-rev>:outputs/verification_set/images/grade4_case1.png` next to
`images/grade4_case1.jpg`.

The phantom generator is still in the codebase and still reachable at
`/demo/{grade}`, now behind a collapsed panel labelled as such. It exists so
the service is demonstrable on a machine with no corpus on disk. It is not
evidence, and no reported number comes from it.

## What this set is, and what it is not

**It is a demonstration, not a measurement.** These twelve were *chosen* from
the held-out split: among the images the deployed model grades correctly,
these are the ones with clean quality and a decisive verdict. Twelve
hand-picked cases cannot tell you how the system performs, and 12/12 is not an
accuracy figure. Quoting it as one would be dishonest.

**The measurement is the whole split.** Run over all 631 held-out real
photographs (APTOS-2019 test + IDRiD test), same weights, same code path:

| | |
|---|---|
| Exact-grade accuracy | **0.783** (494/631) |
| Within one grade | **0.962** |
| Referral sensitivity (grade ≥ 2) | **0.989** (281/284) |
| Referral specificity | **0.839** (291/347) |
| Auto-reported without human review | 44.1% (278/631) |
| Escalated urgent | 50.6% (319/631) |

The full validation report, with confidence intervals, external validation on
Messidor-2, calibration and the ablation, is in
[`outputs/validation_fusionfix/summary.md`](../validation_fusionfix/summary.md).

## The bug this set found

The first run of these twelve — before any of them was chosen — returned
`refer / urgent` for all twelve, including the healthy eyes. Widening it to
the whole split: **631 of 631** real photographs escalated to urgent referral.
A screener that escalates every patient has destroyed the triage that is its
only reason to exist.

Cause: IDRiD ships no neovascularisation masks, so the NV channel of the
segmenter is never supervised on the real cohort. At the default 0.5
threshold it returns a blob on nearly every retina, and `_decide` escalated on
that blob in its very first branch — ahead of the confident-negative guard the
rest of the method is built around. `rule_grade` had always refused to read
that channel when unassessed; the decision rule had not.

One-line fix in `pipeline.py`, pinned by `tests/test_unassessed_escalation.py`.
Effect on the same 631 images:

| | before | after |
|---|---|---|
| Escalated urgent | 631/631 (100%) | 319/631 (50.6%) |
| Auto-reported | 0/631 (0%) | 278/631 (44.1%) |
| Referral specificity | 0.000 | **0.839** |
| Referral sensitivity | 1.000 (trivially) | 0.989 |
| Exact-grade accuracy | 0.781 | 0.783 |

The grade never moved much — the grader was fine. What was broken was the
triage on top of it, and it was broken in the direction that looks safe.

## Reading a report

Each `reports/*_report.html` opens standalone. The banner above the verdict
states what the pixels are:

> **IMAGE OF EYE** — Real image attached — APTOS-2019 (Aravind Eye Hospital,
> India), held-out test split, subject `bcd503c726ba`, 1280×920 px. Never seen
> in training, validation or threshold fitting.

A phantom run through `/demo/{grade}` gets the same banner in amber, saying
`SYNTHETIC PHANTOM — generated, not a photograph. Not clinical evidence.` The
first question anyone asks about a screening output is what it was run on, and
a report that does not answer it lets a demo on generated images be mistaken
for one on a real photograph.

Note the row reading `neovascularization: not assessed`. That is not a "no
neovascularisation" finding — it says the model never looked, because no
corpus in the training pool annotates that class. Proliferative DR is
*defined* by neovascularisation, so reporting "not assessed" as "absent" would
be the difference between "we looked and it is clear" and "we never looked".

## Run it yourself

```bash
git clone https://github.com/yashchoudhary14/SIH-26038.git
cd SIH-26038
python3.11 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install torch torchvision          # or the CUDA wheel for your GPU
pip install -r requirements.txt && pip install -e .
```

The trained weights (`outputs/artifacts/*.pt`) are committed — no download, no
training.

**Browser console (best for presenting):**

```bash
python -m uvicorn drscreen.api:app --port 8000
```

Open <http://localhost:8000>. The twelve photographs appear as a thumbnail
grid with their reference grades; click one and the pipeline runs live. Or
drop any fundus image onto the upload panel.

**Command line:**

```bash
python scripts/run_demo.py --dir outputs/verification_set/images --out /tmp/reports
```
